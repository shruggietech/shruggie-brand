# Security Policy

## Supported versions

Security fixes are applied to the latest released version of the brandbuilder and to the current `main` branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's private vulnerability reporting form on GitHub. If that channel is unavailable, email `info@shruggie.tech` with the affected version, reproduction details, impact, and any suggested mitigation.

Avoid including private brand assets, credentials, or unrelated user data in a report. The maintainers will acknowledge receipt, coordinate validation, and disclose a fix when users have a safe migration path.

## Scope

The most relevant security surfaces are generated registry JSON, package and workflow supply chains, untrusted source content rendered into the static site, release archives, and path handling in build scripts. Brand consistency or trademark-use questions belong in ordinary issues unless they also create a security impact.
