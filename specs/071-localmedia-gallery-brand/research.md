**Date**: 2026-10-21

## Candidate workflow

Decision: Adapt the current private Insonic preparation/finalization pattern to a new pending localmedia.gallery packet, using current identity_continuity APIs.

Rationale: Production staging, source snapshots, complete proofs and exact promotion already exist. A pending packet is independently validated because validate_record intentionally accepts approved-canonical or historical-baseline, not canonical-candidate.

Alternatives considered: Historical baselines cannot approve a new identity. Generated concept art and visual similarity cannot replace exact production source.

## Transparent compound paths

Decision: Add glyphkit.compound for validated closed absolute subpaths and add it to the provenance vocabulary. Preserve primitive path bytes and explicit evenodd fill rules.

Rationale: D combines a rounded tile with transparent mountain/sun/play cutouts. Current helper validation requires every d value to call an approved primitive directly. No existing primitive represents arbitrary compound contours. Surface-colored overlays would be opaque and alter the intended behavior.

Alternatives considered: Hand serialization violates source provenance; Path-based custom serialization is not approved; changing D to avoid its cutouts would narrow the owner's selected direction.

## Renderer and proof policy

Decision: Use installed Windows Node 24.11.0 and resvg 2.6.2 consistently for the candidate, and bind actual renderer settings, Pillow version and all proof hashes.

Rationale: This renderer group is already supported by approved-proof CI. All 32 coordinates use the production path. The canonical light proof ground is #F7F8FC and is measured independently of the proposed light interface surface.

Alternatives considered: Default PATH Node is 26.5.0 and is also supported in a separate CI group; mixing runtimes silently is unnecessary. Native rasterizers take precedence, so probe current capabilities before declaring which renderer was used.
