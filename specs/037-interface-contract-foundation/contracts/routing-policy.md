# Contract: Contextual Operating Modes

## Author

Select Author when the authorized task changes Brand Canon, Interface Canon, brand identity, brand source contracts, generators, adapters, recipes, schemas, or governed instructions. Author retains every existing Spec Kit, approval, identity, provenance, accessibility, publication, and authorization gate.

## Implementation

Select Implementation when the authorized task applies an existing pinned contract inside a consumer repository. Implementation reads the consumer contract and deeper instructions, uses the declared renderer and host, preserves identity authority, avoids a permanent parallel design system, and records reusable gaps locally. It cannot submit upstream, redesign identity, publish, or change governed source without separate authorization.

## Audit

Select Audit when the task assesses conformance, integrity, accessibility, provenance, or adoption without remediation authorization. Audit is read-only and reports evidence, severity, and the appropriate Author or Implementation handoff.

## Conflict rule

Mode inference never grants permission. When a request combines mutation with read-only assessment, identity redesign with simple implementation, or upstream submission without authorization, ask one narrow question that identifies the exact conflicting action. Do not broaden the task.

## Host equivalence

`skill/SKILL.md` is the metadata-aware entry point. `skill/AGENTS.md` is generated from the same body for ambient hosts. The routing section, evidence table, recovery path, and authorization language must remain semantically identical after synchronization.
