# Implementation Plan: WordPress Brand Delivery

**Branch**: `codex/062-wordpress-brand-delivery` | **Date**: 2026-09-27 | **Spec**: [spec.md](spec.md)

## Summary

Complete #273 and #274 in dependency order. Generate a versioned native `theme.json` adapter from approved brand and interface contracts, then package an installable block theme with patterns, templates, fonts, assets, and a client customization workflow. Verify generated bytes and exercise both pinned WordPress/PHP fixtures before claiming support.

## Technical Context

**Language/Version**: Python 3.8 minimum generator, WordPress core 6.9.9/PHP 8.2 and 7.1.2/PHP 8.3 fixture pairs, `theme.json` format 3, Node 24.11 minimum for Docker-based test orchestration.

**Primary Dependencies**: Existing Python generator and version-policy code, WordPress core block editor and Site Editor, `@wordpress/env` pinned in test tooling, Docker on the CI runner. No production theme plugin dependency.

**Storage**: Git-tracked Python/templates/references/docs only; generated kits, theme ZIPs, test sites, and release archives under ignored temporary or `dist/` paths.

**Testing**: Python generator and package tests, exact inventory/checksum validation, pinned clean WordPress install/edit/render/update fixtures, all eight kit `verify.py` and `validate_glyph.py` gates, existing site and release checks.

**Target Platform**: Native WordPress block themes and core editor; adapter output can also guide manual integration into a compatible existing theme without claiming classic/page-builder support.

**Project Type**: Brand-kit compiler plus static site.

**Performance Goals**: No runtime third-party font request; modest theme CSS and only local approved assets.

**Constraints**: Preserve identity geometry, formal versus cue color semantics, WCAG 2.1 AA, current adapter behavior, source/artifact boundary, and exact version provenance.

**Scale/Scope**: Eight production brands, two issue contracts, four starter patterns, six page-state templates, two pinned WordPress/PHP fixture pairs.

## Delivery order

1. Extend version policy and consumer contract for a separate WordPress adapter identity.
2. Generate native palette, typography, layout, and block styles with scoped supplement and support record.
3. Package deterministic installable theme with templates, parts, patterns, fonts, raster logo alternatives, and inventory.
4. Extend verifier, kit/skill/site integration, CI runtime tests, and client handoff.
5. Rebuild all production kits, run site/release audits, record exact test evidence, and publish one PR.
