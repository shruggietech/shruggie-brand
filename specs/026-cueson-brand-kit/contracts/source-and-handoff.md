# Source and Consumer Handoff Contract

## Source boundary

- Production brand source is committed only beneath `brands/cueson/`, with approved shared font inputs beneath `assets/fonts/`.
- Proposal and approval renders, generated kits, PDFs, rasters, registries, static exports, archives, and site output remain beneath ignored generated paths.
- Cueson product files are read-only evidence throughout S026.
- Approved constructed geometry becomes immutable source data after its gate. Later code may arrange or rasterize it only through approved transformations.

## Affiliation

Its generated affiliation contract uses a ShruggieTech parent, house governance and typography, owned-project endorsement, and no third-party service credit. Parent governance does not authorize copying the ShruggieTech mark or using house orange as Cueson's identity accent.

## Handoff manifest

The generated handoff identifies:

- S026 source revision and both approval records;
- approved master and producing-configuration hashes;
- each proposed consumer asset and exact generated hash;
- intended future Cueson repository destination and use;
- license and notice obligations;
- minimum sizes, background, mask, and transformation limits;
- the required future Cueson issue and Spec Kit slice fields;
- an explicit statement that S026 did not modify the Cueson working tree or remote;
- an explicit statement that `cueson.io`, DNS, and Cloudflare were not changed.

## Consumer boundary

The handoff manifest is advisory until Cueson accepts it through its own issue, specification, validation, review, and merge process. S026 does not copy assets into Cueson, commit there, open a Cueson pull request, change release state, or activate the domain.
