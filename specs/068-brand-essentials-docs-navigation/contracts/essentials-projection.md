# Brand essentials projection contract

1. The compiler reads only validated canonical brand source and the existing verified kit asset inventory. It never converts an unresolved or site-metadata-only message to visual-guide prose.
2. The portal's `essentials` object carries exact source text for every included brand-specific role. Hosted, portable, and PDF output preserve the role labels and text; presentation markup may differ.
3. Name and relationship always render. Approved words and Brand strategy render only when at least one role is approved for `visual-guide`. Visual signatures and asset destinations identify the delivered marks, colors, typography, and detailed guide locations. Usage limits include every declared logo prohibition plus exact `guidance.sharp_edge` wording for the three reviewed visual boundaries. PDF gives the full source list its own sheet.
4. Overview-era `foundation`, `promises`, `in_scope`, `out_of_scope`, and product-oriented `sharp_edge` remain in canonical source and inventory for deliberate disposition but are not projected into Brand essentials. The three reviewed visual `sharp_edge` sources are explicitly distinguished from the product-oriented ones.
5. Every contents entry points to a rendered heading and every rendered heading meant for navigation has a matching entry. Sparse brands produce no blank or filler section.
6. The documentation sidebar uses the generated publication record. A release has a labeled version link; a candidate shows only a compact accessible theme control. Neither state shows a version selector.
