# Registry Delivery Contract

## Public paths

- `/{slug}/brand/r/registry.json`: discovery inventory whose entries mirror each direct item payload.
- `/{slug}/brand/r/theme.json`: installable fileless theme with usable light/dark CSS variables.
- `/{slug}/brand/r/{component}.json`: installable UI item with source content and target.
- `/{slug}/downloads/`: full kit with `nextjs/fonts.ts` and local font files for manual setup.

No `fonts.json` item is advertised while the supported external schema cannot represent the bundled local font provider.

## Invariants

1. Catalog and direct payloads have identical names, types, descriptions, dependencies, files, and theme data for each entry; no undeclared direct item is published.
2. Every JSON object validates against a pinned official schema snapshot. Schema URL strings alone are insufficient.
3. Theme `files: []` is valid only when useful CSS variables are present. UI `files` must contain safe paths, target paths, and nonempty source content.
4. Dependencies resolve to declared local items or explicitly allowed external registry names. File targets must stay inside the consumer project.
5. CI tests the exact generated bytes with pinned `shadcn@4.21.0` in temporary consumers before release artifacts are staged.

## Failure cases

Reject missing item endpoints, mismatched catalog projections, invalid provider, empty UI content, missing or unsafe target, duplicate names/targets, broken dependencies, and missing local font files. Diagnostics identify the brand and item.
