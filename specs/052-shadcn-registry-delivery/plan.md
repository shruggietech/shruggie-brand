## Summary

Repair the P0 registry at its generator source. Derive the catalog and direct endpoints from one typed item collection; stop advertising an unsupported local-font item; validate official schema and semantic completeness before publication; prove pinned CLI installation in temporary clean consumers; update all kit, skill, PDF, and hosted guidance. **Primary Dependencies**: Existing BrandBuilder generator and site projection, official shadcn registry schemas, Python JSON Schema validator, Tailwind v4 and Next.js consumer context

**Storage**: Source templates, schema snapshots, and documentation; generated kits and fixtures remain ignored or temporary

**Testing**: Fail-first Python contract tests, isolated CLI consumer test, full production build/glyph gate, site type-check/build/tests, publication audit

**Target Platform**: Offline generated kits and statically exported public brand site

**Constraints**: Bundled local fonts, WCAG 2.1 AA, Python 3.8 compatibility, no generated outputs in Git, no geometry changes, hidden Windows child processes

**Scale/Scope**: All production brands and every advertised item; representative CLI installation from exact generated bytes

## Design Sequence

1. Add fail-first contract cases for catalog parity, invalid provider, missing and empty UI files, targets, dependencies, and legitimate fileless theme.
2. Pin schema snapshots and CLI version, implement reusable validation at generation and site-copy boundaries, then derive catalog entries from the direct item collection.
3. Remove unsupported font item publication and update local font setup across generated README, skill, PDF, and hosted guidance.
4. Add temporary clean-consumer CLI installation and local-font resolution tests, then wire them into CI before publication staging.
5. Run full documented validation, record evidence and remaining post-release checks, sync Spec Kit artifacts, commit, push, open PR, and resolve CI/reviews under the authorized two-round cap.
