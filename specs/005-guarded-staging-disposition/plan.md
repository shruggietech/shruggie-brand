## Summary

Turn the remaining Phase 1 and Phase 10 issues into one guarded operational transaction. S005 first proves tool access, archive coverage, authoritative repository coverage, release availability, provenance preservation, and destination safety. It then writes a private exact recovery record, moves historical and unrelated material to governed cold storage, moves only verified superseded or regenerable material to recoverable deletion staging, and verifies the original workspace is empty. The repository receives a sanitized complete disposition ledger, decision and S004 evidence reconciliation, Spec Kit evidence, and a bounded review ledger. The official pull request receives the automatic Codex review and exactly one requested second round, then stops open at the owner merge gate.

## Technical Approach

1. Reconcile S004 post-merge publication evidence so the v1.1.2 release prerequisite is represented in the repository.
2. Capture a sanitized toolchain baseline and perform an authenticated account-scoped Cloudflare read without publishing credentials or identifiers.
3. Compare each live staging file against the pre-disposition ZIP by normalized path, byte count, and SHA-256. Accept only the two regenerated bytecode cache files as unarchived transient content.
4. Capture one private inventory containing exact resolved paths, sizes, hashes, destination roots, collision checks, and recovery instructions; derive a sanitized top-level ledger for `docs/disposition.md`.
5. Prove authoritative repository coverage for skill sources, shared fonts, five brand sources, CSS provenance, Fragcap construction files, and SVG runtime helper behavior; recheck the published seven-asset release and live site prerequisites.
6. Resolve exact private cold-storage and recoverable-deletion roots. Reject any source outside the staging root, any destination outside its approved root, and any existing destination collision.
7. Move historical bulk output, unrelated research, private session output, and the operator directive to governed cold storage. Prefer cold storage whenever an owning-project destination is ambiguous.
8. Move private skill copies, transport bundles, five superseded brand directories, five snapshots, the regenerable runtime, and verified provenance originals to recoverable deletion staging. Do not permanently delete anything.
9. Verify every destination item against the pre-move inventory, confirm the original staging workspace has zero files and zero undocumented directories, and finalize both recovery and public evidence.
10. Run focused policy checks, full six-target validation, site validation, encoding and sensitive-data scans, and a clean-checkout repetition.
11. Create and link the S005 GitHub slice issue, push the implementation, and open the official pull request with the bounded review ledger.
12. Process automatic Codex round 1 completely, file every negative finding as an issue, post exactly one `@Codex` request, process round 2 completely, and wait for required checks.
13. Stop with the pull request open. After owner merge, verify actual main, close direct child issues before parents, close milestones only at zero open issues, close S005, and update program #37 without disturbing the separately owned downstream issue.

## Architecture Decisions

- The private recovery record is the only place exact operational roots and recovery instructions appear. Public evidence identifies destination classes and integrity results only.
- The existing archive is reused because every one of its 2,479 files matches live content. The only unarchived files are two generated Python bytecode caches, so a duplicate archive would add no authoritative coverage.
- Authenticated Cloudflare API access satisfies the work-order access gate even though the local CLI and token environment variable are absent. The preflight requires a successful account-scoped read.
- Governed cold storage is the default for unrelated or historical content when its owning-project destination is missing or ambiguous. S005 will not mutate another repository on inference.
- Recoverable deletion staging receives only content already proven present in the repository, the release, provenance, the backup, or reproducible dependency declarations.
- Same-volume directory moves preserve large virtual-environment and dependency trees without traversing junction targets. Exact path validation and collision rejection precede each move.
- The public ledger records each legacy brand directory and archive separately even when they share the same preservation proof.
- GitHub closure follows current-main evidence. Branch completion may satisfy operational cleanup, but it does not close implementation-dependent issues or milestones before the owner merge.
- Review requests form a finite state machine: automatic round 1, one explicit round 2, complete. Correction pushes and late feedback never create another request.
